# SYNC-11 · UI-03 명세 및 RTM 개정 제안

기준: `75a9882` / 2026-10-22 사용자 요청, 2026-10-24 후속 실행. 기존 명세를 덮어쓰지 않는 **개정 제안**이다. 이번 실행 결과는 별도 보고서와 원본 증거를 기준으로 읽는다.

## 판단 출처와 범위

사용자가 직접 지정한 판정 기준: 충돌 시 서버 선행 저장 보존, B의 미저장 메모와 안내 유지, 사용자 직접 재저장, 다른 필드 덮어쓰기·자동 재저장·재충돌 검사, 단위 선택 제거와 cm 고정, 기존 `preferredUnits` 무영향. 이것을 이번 실행의 수용 기준으로 사용했다. 과거 9월 결정의 작성자나 승인 내역을 이번 실행으로 소급해서 변경하지 않는다.

Codex가 수행한 일: 기존 문서와 테스트 분석, 격리 환경 구성, 기존 API 테스트 실행, 추가 재현 스크립트 작성, 요청·응답·SQL 조회·스크린샷 수집, 증거에 따른 판정과 아래 개정안 작성. 추가 경합 실험과 수정 설계는 Codex의 검증·기술 제안이다. 제품 정책의 확정이나 사용자의 수동 실험으로 기록하지 않는다.

## SYNC-11 본문 제안

프로젝트 수정은 마지막으로 조회한 서버 버전(`baseUpdatedAt`)을 전송한다. 서버가 이미 갱신됐으면 저장과 자식 변경을 적용하지 않고 409 `PROJECT_CONFLICT` 및 서버 최신본을 반환한다. 같은 기준 버전으로 겹쳐 도착하는 요청도 최대 한 건만 성공해야 한다.

클라이언트는 충돌 후 서버 최신 프로젝트와 저장 기준을 다시 조회하되, 작업 화면에서 편집 중인 메모 입력을 유지하고 저장 실패와 보존 사실을 안내한다. 자동으로 재저장하지 않는다. 사용자가 저장을 다시 눌렀을 때 최신 기준을 사용하며, 다시 충돌하면 같은 보호 절차를 반복한다. 메모 재저장은 최신 프로젝트의 다른 필드·자식을 이전 스냅샷으로 덮어쓰지 않아야 한다.

보존 범위는 우선 `memoText`로 명시한다. `currentRow`는 코드상 보존 경로가 있으나 메모 충돌 검증을 근거로 전체 카운터 편집이나 모든 폼·도안 그리기 입력까지 승인하지 않는다. 화면 이탈·앱 종료·오프라인·재조회 실패 때의 초안 수명은 별도 결정 사항이다. 카운터 개별 API 등의 충돌 범위도 기존 명세와 구분한다.

## UI-03 본문 제안

MVP의 온보딩·회원가입·프로필 편집에는 단위 선택을 제공하지 않는다. 게이지 길이 입력과 계산은 cm를 사용하며 설정 메뉴·설명도 단위 선택 기능이 있는 것으로 안내하지 않는다. `preferredUnits`는 과거 데이터 호환을 위해 남을 수 있으나 현재 게이지 계산 단위를 바꾸지 않는다. 데이터 필드 제거·기존 값 일괄 변환은 이번 정책에 포함하지 않는다.

계산 예: 8cm에 20코, 10cm에 30단이면 10cm 게이지는 25코/30단이며 목표 40×55cm에는 100코/165단이 필요하다. 반올림·유효 입력 경계는 기존 게이지 명세/테스트와 연결하고 단위 UI 제거만으로 계산 정확성을 판정하지 않는다.

## 후속 RTM 반영 원칙

- SYNC-11을 순차 stale-write 보호(이번 두 기기 실행)와 동시에 겹친 저장의 원자적 보호(기존 서버 실험)로 나눠 각 상태를 기록한다. 전자의 PASS가 후자의 FAIL을 해소하지 않는다.
- 최종 완료 시도의 결과는 이 폴더 `report.md`, `case-results.md`, `evidence/final-case-results.json`에 연결한다. 이전 미실행 보고서와 중간 환경/하네스 실패는 역사적 실행 이력으로 남긴다.
- UI-03은 A/B 기기별로 온보딩5단계, 가입, 프로필, 설정, 과거4종 단위값의 실제 계산을 기록한다. 단위별 SQL 반환값과 그 기기 실행 단계의 GET /profile 응답을 함께 연결한다.
- 메모 재저장 보존의 확인 필드는 이름·즐겨찾기·단수다. 추가 UI 보완 시도에서는 A가 UI로 수정한 이름이 B의 재저장 뒤 유지됨을 확인했다. 모든 필드·모든 편집 화면의 보존을 승인하지 않는다.
- 자동 재저장 없음은 관찰한 30초 범위로 한정한다. 장시간/오프라인/백그라운드/앱 종료 후 초안 지속은 별도 TC로 둔다.

기존 SPEC/RTM 원문에는 이번 실행 폴더 링크와 케이스 상태를 승인 후 반영하도록 제안한다. 원문은 직접 변경하지 않았다.
