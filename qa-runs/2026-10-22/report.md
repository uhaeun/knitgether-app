## 신규 결함과 원인

**QA-SYNC11-RACE — 두 갱신이 같은 버전을 읽고 모두 성공함.** 전체 20회 중 19회 재현했다. 서로 다른 메모를 가진 양쪽 요청이 200을 받지만 최종 DB에는 하나만 남는다. 실제 서버·DB에서 확인한 제품 결함이며, 단순한 테스트 기대값 오류나 프록시의 부작용으로 볼 근거가 없다.

서버는 트랜잭션 안에서 기존 프로젝트를 읽고 버전을 비교한 뒤 `where: { id }`만으로 갱신한다. 버전 확인과 갱신이 원자적 조건으로 묶이지 않아 두 요청이 같은 이전 값을 읽으면 모두 통과할 수 있다. 조건부 UPDATE 또는 행 잠금 후 버전 비교를 검토하고, 거부된 요청의 자식 변경도 롤백되는 회귀 검사를 추가해야 한다. **수정 제안만 작성했으며 제품 코드는 고치지 않았다.**

기존 [GitHub #14](https://github.com/uhaeun/knitgether-app/issues/14)는 순차 요청과 기준값 필수화로 종료돼 있다. 이번 결과는 그 영향 영역의 **새로 발견한 동시 실행 미커버 경로**로 분류한다. 전체 GitHub 이슈의 중복 검색 완료나 독립 신규 이슈 확정을 의미하지 않는다. 이슈 생성·재개·댓글 작성은 하지 않았다. 심각도는 Major / 우선 수정 검토를 제안하며 최종 결정은 제품 오너에게 남긴다. [결함 상세](DEF-SYNC11-RACE.md).

## 격리와 보존

전용 PostgreSQL 14.18 / 포트 55432 / `knitgether_qa_20261022`, Nest 3301, 기록 프록시 3300, 실행 폴더의 파일 저장소를 사용했다. 기존 3000 서버·5433 DB·docker-compose 볼륨·기존 테스트 계정은 건드리지 않았다. `db:reset-test`를 실행하지 않았다. SQL 조회와 덤프는 이 전용 DB만 대상으로 했다. [환경 및 재실행 안내](RUNBOOK.md).

요청·응답은 [http.jsonl](evidence/http.jsonl), 단계별 DB는 `api-sequential-db.json` 및 `api-concurrency*.json`, 전체 테스트 DB는 로컬 `evidence/isolated-db.dump`로 보존한다. 덤프와 세션 식별자는 Git 추적에서 제외했다. 인증 헤더를 수집하지 않았고 응답 토큰·비밀번호는 마스킹했다.

삭제한 사용자 영역 파일은 npm·CocoaPods·비활성 Gradle·pip의 재생성 가능한 캐시다. 실패한 이번 빌드 산출물과 이번에 만든 대체용 iOS 18.5 기기 외의 프로젝트·QA 증거·DB·시뮬레이터 데이터는 삭제하지 않았다. 캐시 제거로 향후 관련 도구의 다운로드·빌드가 다시 필요할 수 있다. 현재 공간은 다른 앱과 OS 스왑에 따라 달라지므로 `cleanup.txt`의 실측 시각과 함께 읽는다.

## 포트폴리오용 요약

> 나는 동시 수정 시 서버 선행 데이터와 미저장 입력을 보존해야 한다는 기준, cm 고정 정책, 검증 우선순위를 정했다. Codex는 격리된 서버·DB에서 기존 API 회귀 18건을 실행해 모두 통과시켰다. 추가 동시 요청 실험에서는 두 저장이 함께 성공하는 미커버 경로가 20회 중 19회 재현됐고, 응답과 DB 값을 대조해 무통보 덮어쓰기를 확인했다. iOS 두 기기 및 단위 정책의 화면 검증은 자동화 환경 문제로 미실행 처리했으며, API 통과를 E2E 통과로 확대하지 않았다. 사용자 판단과 Codex의 실행·구현을 구분해 증거와 후속 검증 범위를 남겼다.
