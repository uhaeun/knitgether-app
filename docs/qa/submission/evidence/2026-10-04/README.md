# 도안 교체와 페이지 복귀 추가 검증

2026-10-04에 사용자의 요청으로 Codex가 Appium을 실행해 촬영한 원본 화면입니다. 8월과 9월의 기존 수행 이력과 구분하는 추가 재검증 자료입니다. 생성형 이미지로 앱 화면이나 검증 결과를 만든 것이 아닙니다.

## 환경과 촬영 방법

- 환경: iPhone 17 Pro Max 시뮬레이터, iOS 26.5, 설치된 KnitGether 1.0 (1)
- 도구: Appium 3.1.2, XCUITest, Python 촬영 스크립트
- 실행 모드: 앱 로컬 저장소. API 서버와 DB 동기화는 이번 촬영의 검증 대상이 아닙니다.
- 입력: 직접 만든 테스트용 PDF A 4페이지와 PDF B 2페이지. 상업용 도안을 사용하지 않았습니다.
- 화면: Appium의 `save_screenshot`으로 저장한 원본 PNG. 이미지 내부에 결과나 문구를 덧그리지 않았습니다.
- 데이터: 연습용 시뮬레이터의 앱 데이터를 백업한 뒤 테스트 프로젝트를 준비했습니다. 촬영 후 원래 앱 데이터를 복원하고 백업 파일 15개의 해시 일치를 확인했습니다.
- 빌드 출처: 새 소스 빌드를 완료하지 못해 이미 설치된 앱을 사용했습니다. [설치 앱 정보와 실행 파일 해시](installed-app.json)를 기록했습니다. 저장소 HEAD와 설치 앱의 소스 커밋이 같다고 단정하지 않습니다.

## 도안 페이지 복귀

테스트 도안 A의 1페이지에서 3페이지로 이동한 것을 먼저 확인했습니다. 본문에 있는 고유 표시 `PATTERN A-03`이 실제 화면에 보이는지 접근성 XML과 PNG에서 확인했습니다.

| 순서 | 실제 확인 | 원본 화면 |
|---|---|---|
| 이동 전 | 3페이지의 고유 표시 노출 | [화면](page-verified/07_page_before.png) |
| 홈 이동 | 프로젝트 목록을 나와 홈 탭 진입 | [화면](page-verified/08_home_between.png) |
| 홈에서 복귀 | 같은 프로젝트에서 3페이지 표시 | [화면](page-verified/09_page_after_home.png) |
| 사전 조회 | 도안 보며 찾아보기 화면 진입 | [화면](page-verified/10_lookup_between.png) |
| 사전에서 복귀 | 완료 버튼으로 닫은 뒤 3페이지 표시 | [화면](page-verified/11_page_after_lookup.png) |

최종 실행에서는 페이지 이동, 홈 복귀, 사전 화면 닫힘, 사전 복귀를 검사한 4개 조건이 통과했습니다. [최종 실행 원본](page-verified/events.jsonl)

이 검증의 기준은 기존 요구사항에 있는 같은 페이지로의 복귀입니다. 페이지 안에서 본문이 놓인 세로 위치는 이동 전 334pt, 복귀 후 429pt로 달랐습니다. 세부 스크롤 위치까지 같다고 주장하지 않습니다.

초기 시도에서는 기존 화면 읽기 함수가 빈 목록을 반환했고, 후속 시도에서는 요구사항에 없는 픽셀 위치 일치 조건과 사전 화면을 닫지 못한 조작 때문에 중단됐습니다. 실패를 앱의 페이지 초기화 결함으로 합산하지 않았습니다. 실제 화면 구조와 요구사항을 대조한 뒤, 빈 결과를 허용하지 않는 페이지 표식 검사와 완료 버튼 조작으로 재실행했습니다. 초기 기록은 이 폴더의 `events.jsonl`과 [사전 닫기 조작 실패 기록](page-check/events.jsonl)에 남겼습니다.

초기 진단의 `failure.png`는 후속 실패 촬영으로 덮어써져 최초 실패 화면의 원본이 남아 있지 않습니다. 해당 시점의 로그 해시와 현재 파일은 일치하지 않으며, 이 파일은 포트폴리오 본문의 사진으로 사용하지 않았습니다. 본문에 사용한 사진 8장은 모두 촬영 로그의 해시와 일치합니다. 이후 촬영 스크립트에는 기존 실행 폴더를 덮어쓰지 않는 검사를 추가했습니다.

- `events.jsonl`에는 실제 수행 시각, 검사 결과, 이미지의 SHA-256 해시가 있습니다.
