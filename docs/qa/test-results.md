# 테스트 결과

초기 수동 테스트에서 사용자 흐름과 실패 조건을 확인하고, 수정 뒤 반복 확인할 항목을 UI, API, Swift와 실제 DB 테스트로 옮겼습니다. 아래 결과는 실행 시점과 계층을 나누어 적었습니다. 서로 다른 테스트의 수치를 더해 전체 E2E 통과 건수로 표시하지 않습니다.

## 최초 수동 실행

설계 22건 중 21건을 수동 실행했습니다. `TC-SYNC05-01`은 원격 조회와 병합의 사전 조건을 수동으로 만들기 어려워 단위 테스트로 대체했습니다. 최초 판정은 **10 PASS, 11 FAIL**입니다. 단수 하한 결함 DEF-15를 수정해 재실행한 결과를 포함한 사이클 기록은 **11 PASS, 10 FAIL**입니다.

| 트랙 | 수동 실행 | 사이클 기록 | 범위 |
|---|---|---|---|
| 사용자 흐름과 연결 정합성 | 4 | 3 PASS, 1 FAIL | 핵심 흐름 3개와 연결 생애주기 1개 |
| P1 실패 조건 | 6 | 0 PASS, 6 FAIL | 동기화 거부와 충돌, 계정 전환 |
| 기능과 경계 조건 | 11 | 8 PASS, 3 FAIL | 단수, 캐시, 파일, 토큰 만료 등. DEF-15 수정 후 PASS 포함 |

기준 빌드 `bf2b001`과 당시 작업 화면 UX 개편 빌드를 사용했습니다. SQL 조회, HTTP, 서버 로그, 로컬 파일을 화면과 대조했습니다. 다음 세 사용자 흐름은 당시 수동 실행의 통과 근거입니다.

| 흐름 | 실제 확인 |
|---|---|
| 첫 사용 | 두 경로의 프로젝트와 4종 자료 연결 결과를 SQL로 대조 |
| 작업 재개 | 로그인과 연결 자료, 단수 3 유지. 증가 후 DB 단수 4 확인 |
| 기법 조회 후 복귀 | 단수 5와 도안 3페이지 유지 |

반면 정상 흐름의 통과가 예외 상황의 안전성을 보장하지는 않았습니다. 오래된 요청이 작업 세션을 삭제했고, 실제 400 거부 뒤 로컬 기록이 사라졌으며 계정 전환 뒤 이전 기록이 표시됐습니다. [결함과 원인](defects.md)에 최초 FAIL과 수정 근거를 연결했습니다.

## 실패 분석에서 바로잡은 판정

| 상황 | 확인과 정정 |
|---|---|
| 필수 단수 정보 누락 | 처음에는 앱 배열 디코딩 실패를 의심. SQL로 한 항목의 단수 정보를 제거하고 HTTP를 보니 서버의 응답 변환 단계에서 목록 전체 500 발생 |
| 캐시가 조회 실패를 가림 | 정상 프로젝트의 서버 단수를 22에서 99로 변경해도 앱이 22를 표시. 화면에 목록이 있다는 이유로 조회 성공으로 판정하지 않음 |
| 숫자 타입 검증 우회 의심 | 프록시 수정값에 따옴표가 남아 문자열로 전달됨. 순수 숫자 요청은 400이었으므로 제품 결함으로 확정하지 않음 |
| 페이지 복귀 UI 테스트 | 기존 판정은 빈 결과도 통과할 수 있었음. 실제 3페이지 고유 표시와 중간 화면 도착, 복귀를 확인하도록 보완 |
| 후속 API 전체 실행의 5 FAIL | 테스트 프록시가 전용 서버가 아닌 기존 서버를 참조한 준비 오류. 주소를 맞춰 재실행했고 제품 수정 효과로 세지 않음 |

## 최신 회귀와 실기기 결과

2026-10-31 결과입니다. 계층별 회귀 소스는 `82acccc`, 카메라 안내와 실기기 앱 소스는 `5bcbaae`, 최종 기기 자동화의 대화상자 처리 소스는 `f0663a6`입니다. 계정, DB, 저장 경로와 포트를 개발 환경에서 분리했습니다.

| 실행 계층 | 결과 | 확인한 범위 |
|---|---|---|
| 서버 회귀 | 180 PASS | HTTP 계약, 입력, 저장 경로 |
| 실제 PostgreSQL과 HTTP | 40 PASS | 경합, 롤백, 연관 데이터와 파일 정합성 |
| API, 네트워크, DB | 79 PASS, 0 xfail | 기존 실패의 조건별 회귀. 결손 관련 5개 포함 |
| Swift 내부 테스트 | 365 PASS / 41 suites | 미저장 입력, 캐시와 파일, 상태와 오류 처리 등 |
| iPhone 16 Pro 로컬 흐름 | 고유 시나리오 최종 2 PASS | 단수의 백그라운드와 재실행 후 보존, 카메라 거부 안내 후 작업 복귀 |
| iPhone 계정과 서버 연결 | 미완료 | 가입 요청에서 `-1009 / Local network prohibited` 반복 관찰 |

실기기는 iOS 27.0.1, Xcode 26.6의 별도 QA 앱입니다. 최종 로컬 2개는 비로그인 지원 경로로 실행했습니다. 서버 연결을 전제로 시도한 네 흐름의 통과로 대체하지 않았습니다. 실행기의 HTTP 401 응답도 앱의 가입과 서버 동기화 성공을 뜻하지 않습니다.

### 필수 단수 정보 누락의 보완

- 정상 프로젝트는 200으로 반환합니다. 내 프로젝트의 필수 단수 정보가 없거나 사용할 수 없으면 개별 조회는 409와 `PROJECT_ROW_COUNTER_MISSING`, 타 계정은 기존 404를 반환합니다.
- 목록은 정상 항목을 200 배열로 반환하고, 제외한 ID를 헤더로 전달합니다. 앱은 이 항목의 캐시를 실제 삭제로 오인해 제거하지 않습니다.
- SQL로 주입한 삭제, 삭제 표시, 소유자 불일치를 테스트했습니다. GET 전후 프로젝트와 작업 세션이 바뀌지 않는지 대조했습니다.
- 단수를 0으로 추정하거나 GET으로 데이터를 복구하지 않습니다. 복원 시험은 확보한 정확한 카운터 사본을 전용 DB에 되돌린 것입니다.

보완 전 강화한 기준의 4 FAIL과 수정 후 결과, 환경 준비 오류, 카메라 테스트의 조작 실패와 제품 안내 수정은 [최신 실행 기록](evidence/2026-10-31/README.md)에 함께 보존했습니다. 원격 CI 수치와 로컬 수치도 같은 문서에서 구분합니다.

## 남은 확인

- 실제 iPhone의 가입, 계정 전환과 서버 동기화. 로컬 네트워크 거부는 관찰했으나 허용 이후 반복 거부의 원인은 미확정입니다.
- 장시간 부하, 여러 OS와 기기 조합, Wi-Fi와 이동통신 전환, 실제 스캔 품질.
- DEF-27과 DEF-28의 수정 동작은 전용 테스트 근거가 없습니다. 빌드 성공과 동작 검증을 구분합니다.
