이번 검토는 AI 도구 Codex가 수행했습니다. 기존 QA 수행 이력과 별도로 기록합니다.

## 수정한 내용

1. 프로젝트 요약과 상세 QA 기록의 읽기 순서를 분리하고 전체 목차를 추가했습니다.
2. 과거 설계와 개발 문서에 기준 시점 안내를 붙였습니다. 사라진 원문은 검증한 Git 이력 링크로 연결했습니다.
3. 비공개 작업 문서를 가리키던 링크와 Appium 폴더 이동으로 깨진 링크를 정리했습니다.
4. 1차 설계 22건과 수동 수행 21건을 구분했습니다. 수정 후 PASS가 포함된 집계를 최초 결과처럼 쓰지 않도록 했습니다.
5. “검출률 100%”, “모든 API 판정에서 SQL 조회”와 단독 코드 작성으로 읽히는 역할 표현을 바로잡았습니다.
6. API 안내를 현재 20개 파일에 맞추고, 오래된 충돌 감지 설명을 수정했습니다.
7. Postman 생성 요청에 현재 서버가 요구하는 프로젝트 ID, 카운터와 기타 필수값을 추가했습니다.
8. UI-51에서 빈 도안 본문을 정상으로 비교하는 상황을 차단하고, 페이지 이동과 사전 화면 종료를 확인하도록 했습니다.
9. 결함 주입 도구가 기존 편집 파일을 되돌릴 수 있는 경로와 ERROR를 검출 성공으로 집계하는 문제를 수정했습니다. 다른 서버 프로세스를 강제 종료하는 동작도 제거했습니다.
10. 과거 API 진단 스크립트가 거부된 PATCH 요청을 보존 성공으로 판정하지 않도록 조건을 보완했습니다.

## 추가 내용 검토에서 수정한 사항

- 기획 원문에 섞인 AI 요청문과 작업 대화는 Git 이력 링크로 보존하고, 현재 기능 정의로 연결하는 안내를 추가했습니다.
- 개인 작업 지시와 편집 메모를 정리했습니다. 미확정 사양이나 검증 공백은 삭제하지 않고 본문에 남겼습니다.
- 문서에 근거 없이 적힌 Python 숙련도와 도구 우열 설명을 제거했습니다. XCUITest UI 테스트의 실행 구조 설명도 바로잡았습니다.
- 일부 실험을 전체 검출력으로 확대한 표현, 화면의 수정일 표시를 저장소 검증으로 해석한 표현, 과거 보안 점검을 현재 안전성 보증처럼 쓴 표현을 수정했습니다.
- Appium 실행 안내의 서버 필요 항목을 현재 수집 결과인 6개 파일, 16개 항목으로 갱신했습니다. 수집은 실제 실행이 아닙니다.
- 앱 번들에 있던 외부 도안 PDF 4개는 공개 재배포 허용 근거를 확인할 수 없어 자체 생성한 테스트 격자로 교체했습니다. 파일명과 11, 9, 3, 17쪽의 페이지 수를 유지했습니다. [자료와 생성 코드 안내](../../../KnitGether/Resources/SamplePatterns/README.md)
- 관리 화면의 숫자가 실제 서비스 운영 지표로 보이지 않도록 Demo와 예시 데이터 표시를 넣었습니다.

기존 증거 이미지는 재작성하거나 대체하지 않았습니다. 이전 도안 파일은 과거 커밋에 남아 있으며, Git 이력을 삭제하거나 재작성한 작업은 아닙니다.

## 남은 확인

- 변경된 UI-51 두 케이스는 전용 시뮬레이터에서 다시 실행해야 합니다. 도안 본문을 읽을 수 없는 환경에서는 이제 확인 불가로 실패합니다. 최근 별도 촬영의 PASS를 변경된 테스트의 통과로 대신하지 않습니다.
- 결함 주입 도구는 파일 복원과 결과 판정만 독립 검증했습니다. 실제 코드 주입, 앱 재빌드와 서버 구동까지의 전체 실험은 이번에 수행하지 않았습니다.
- PDF에 인용한 과거 테스트는 당시 기록입니다. 앱 전체의 최신 통과, 다양한 실기기 지원과 성능 검증 완료를 뜻하지 않습니다.
