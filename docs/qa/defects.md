# 결함과 수정 확인

최초 수동 실행과 후속 설계에서 기록한 **DEF-01~29는 결함 29건**, `SPEC-PROJ-01`은 프로젝트 이름 규칙을 추가한 명세 항목입니다. 합계 30개 관리 항목을 결함 30건으로 세지 않습니다. 당시 대장에는 모두 수정 커밋이 있으나, 이슈 종료와 수정 동작의 실행 확인은 구분합니다.

심각도는 데이터 유실, 계정 간 노출과 사용 불가를 Critical, 기능과 표시 정합성 문제를 Major, 안내와 사용성 문제를 Minor로 나눴습니다. 파일 누적과 참조 불일치는 별도 운영 위험으로 관리했습니다. 테스트 우선순위는 [설계의 위험 기준](test-design.md#우선순위를-정한-이유)에 따릅니다.

## 사례 1: 목록이 보인다는 이유로 조회 성공으로 보지 않았습니다

**조건과 실패:** 전용 DB에서 한 프로젝트의 RowCounter만 SQL로 제거했습니다. 기대는 오류 항목만 격리하는 것이었으나 목록 전체가 500이 됐고 앱에는 예전 캐시가 남았습니다. 정상 프로젝트의 서버 단수를 22에서 99로 바꿔도 화면은 22였습니다.

**원인 정정:** 처음 의심한 앱의 배열 디코딩 전에, 서버가 각 항목을 응답으로 바꾸는 `toResponse`에서 예외를 던졌습니다. `map` 중 한 항목의 예외가 전체 목록 변환을 중단했습니다. HTTP와 SQL 대조 후 원인을 서버로 정정했습니다.

**수정 확인:** 목록의 정상 항목 반환을 확인한 뒤, 후속에는 개별 조회 500과 목록에서 빠진 항목의 캐시 삭제 위험도 테스트했습니다. 내 오류 항목은 409, 타 계정은 404, 정상은 200으로 구분하고 목록 제외 ID를 헤더로 전달했습니다. GET이 저장값을 바꾸지 않는지도 SQL로 대조했습니다. 결손은 시험 DB에 SQL로 주입한 조건입니다. [HTTP, SQL과 회귀 결과](evidence/2026-10-31/README.md)

## 사례 2: 도안 교체에서 취소와 승인을 분리했습니다

**조건과 실패:** 드로잉을 저장한 도안 A를 B로 교체했습니다. 확인과 삭제 안내 없이 교체되어 선이 사라졌습니다. 교체 기준은 개발 전에 확정된 문서가 아니라 QA 설계 과정에서 기존 기획과 사용 의도를 구체화한 기준입니다.

**판정과 수정 확인:** 취소하면 도안 A와 선, DB 참조가 유지되고, 승인하면 B로 바뀌며 이전 선의 참조가 남지 않아야 합니다. 확인창 수정 후 UI 테스트에 옮겼습니다. 후속 직접 교체 실행은 취소, 승인, 재실행 후 상태를 화면으로 대조했습니다. 해당 실행은 로컬 모드이며 설치 앱 커밋이 미확정이어서 서버 동기화의 통과로 확대하지 않습니다. [화면과 실행 조건](evidence/2026-10-04/README.md)

## 사례 3: 충돌을 막은 뒤에도 미저장 입력의 수명을 확인했습니다

**조건과 실패:** 같은 프로젝트를 두 기기에서 수정하고 늦은 요청을 보냈습니다. 초기에는 요청 본문에 없는 작업 세션을 삭제하는 전체 교체 방식이 새 세션을 지웠습니다. 수정 뒤에는 연관 행 변경이 부모 버전을 갱신하지 않는 경로와 메모가 프로세스 종료 후 사라지는 경로를 추가로 확인했습니다.

**원인과 보완:** 서버는 부모 버전 비교와 연관 변경을 같은 트랜잭션에 두어 오래된 저장을 거부하도록 보완했습니다. 클라이언트의 미저장 메모는 ViewModel에만 있어 종료 뒤 잃었으므로 계정과 프로젝트별 파일 초안으로 저장했습니다. 서버 업로드 대기열과는 별도입니다.

**수정 확인:** 두 기기 충돌에서 선행 저장, 409, 미저장 입력 유지와 명시적 재저장을 대조했습니다. 저장 성공과 명시적 폐기, 프로젝트 삭제 뒤 초안 정리를 확인했고, 실패한 삭제에서는 초안을 유지하도록 보강했습니다. 계정 분리는 Swift 테스트에서 확인했으며 전체 계정 전환 UI의 실기기 완료를 뜻하지 않습니다. [화면과 DB](evidence/2026-10-26/README.md) / [당시 전체 보고서](https://github.com/uhaeun/knitgether-app/blob/b2f916bb9b248291a7f7ef421eb7739fda103d11/qa-runs/2026-10-26-session-fix/report.md)
