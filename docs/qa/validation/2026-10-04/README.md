## 실행 중 발견하고 보완한 사항

### 가입 후 화면 이동을 막은 시스템 창

가입과 로그인은 성공했지만 iOS의 암호 저장 창이 남아 뒤로가기나 프로젝트 진입을 막았습니다. XCUITest의 처리 목록에는 한국어 버튼인 “지금 안 함”이 없었고, Appium의 로그인 절차에는 이 창을 처리하는 단계가 없었습니다. 테스트에서 해당 창을 닫도록 보완하고, 온보딩에서 제거된 설정 단계를 반영했습니다. 재실행에서 가입, 스킬 테스트와 프로젝트 생성까지 진행됨을 확인했습니다. GitHub의 새 시뮬레이터에서는 뒤로가기 버튼의 타격점이 잘못 계산되어 이동하지 않았는데도 다음 단계로 넘어가는 문제를 추가로 확인했습니다. 실제 버튼 중앙을 누르고 온보딩 또는 설정 화면에 도착했는지를 확인하도록 보완했습니다. 초기화한 로컬 시뮬레이터와 GitHub에서 대표 흐름을 다시 실행해 통과했습니다. 로그아웃 후 설정으로 돌아가는 항목도 로컬에서 통과했습니다.

### 게이지 입력의 키보드 초점

입력 칸을 연속해서 누른 뒤 키보드 초점을 잃어 테스트가 중단됐습니다. 또한 기존 값과 안내 문구가 모두 `10`일 때 기존 값을 지우지 않아 `1010`이 입력됐습니다. 입력 전후 키보드 정리, 길게 눌러 전체 선택, 기존 값 삭제와 키보드가 사라질 때까지 기다리는 절차로 바꾸고 입력값을 직접 확인하도록 보강했습니다. 기대값은 완화하지 않았습니다. 가입부터 저장까지의 대표 흐름과 게이지 측정값 유지, 목표 수정과 삭제 후 재실행 항목 모두 수정 후 통과했습니다.

### 삭제 완료와 화면 방향의 판정

실 삭제 직후 서버의 삭제 처리와 화면 전환이 끝나기 전에 항목을 검사해 실패했습니다. 실패 후 화면에서는 빈 창고가 보였고, PostgreSQL에서도 해당 실의 삭제 시각이 기록됐습니다. 실, 바늘과 도구 검사는 항목이 사라지는 것을 기다린 뒤 판정하도록 바꿨습니다.

앞선 실행 화면 테스트가 남긴 가로 방향이 다음 기능 테스트로 이어져 입력 칸이나 프로젝트가 화면 밖에 놓이는 문제도 확인했습니다. 기능 테스트의 시작 방향을 세로로 지정하고, 단수 회귀 테스트는 저장한 프로젝트가 목록에 보일 때까지 이동하도록 보완했습니다. 별도의 가로 방향 실행 확인은 기존 실행 화면 테스트에 유지했습니다.

### 도안 페이지 판정 기준

페이지 복귀 검사 두 건은 빈 스크롤 영역을 선택해 도안 본문을 읽지 못했습니다. 실패 시 남긴 화면과 요소 기록에는 실제 PDF 글자가 존재했습니다. PDFKit이 노출하는 빈 내부 스크롤 영역 대신 본문을 포함한 영역을 선택하도록 수정했습니다. 빈 값은 계속 실패로 처리하며, 화면 이탈 전에 페이지가 실제로 이동했는지도 확인합니다.

또한 같은 4쪽으로 돌아왔는데 페이지 안의 스크롤 위치가 달라 본문 일부가 다르게 보이는 경우를 구분했습니다. 기존 [기능 정의의 SPEC-PAT-05](../../../spec/기능정의서_MVP.md)는 페이지 번호를 보존하며 확대율과 페이지 내 스크롤 위치는 보존 대상이 아닙니다. 이 기준에 맞춰 화면에서 가장 넓게 보이는 PDF 페이지의 고유 표식을 비교합니다. 표식 자체가 화면 위로 벗어나도 해당 페이지의 영역과 표식을 함께 읽으며, 화면 밖에 캐시된 이전 페이지는 제외합니다. 다른 페이지, 표식이 없는 경우나 두 페이지가 같은 면적으로 보이는 모호한 경우는 실패합니다.

### 진행 사진의 선택과 저장 확인

진행 사진 테스트는 크기만으로 사진을 골라, 사진 선택창 뒤의 큰 배경 이미지를 누르고 있었습니다. 실제 사진 격자 항목을 선택하도록 범위를 좁혔습니다. 사진 선택 시 자동으로 저장되는 현재 동작을 소스와 화면에서 확인해 별도의 편집 화면을 요구하지 않도록 했습니다. 저장 직후와 앱 재실행 후에는 실제 진행 사진 행이 존재하는지도 확인합니다.

### 테스트 환경의 분리

Appium 주소와 WDA 포트를 환경변수로 지정할 수 있게 했습니다. 네트워크 차단 테스트가 별도 API 주소를 설정해도 기본 서버로 전달되던 부분을 수정했습니다. 결함 주입 도구는 실제 빌드 폴더와 설치할 앱의 경로가 다르면 실행을 중단합니다.

### 누락된 사진 저장 검증

실, 바늘과 도구 사진에 대해 업로드, 교체, 삭제, 파일 내용, DB 경로와 다른 계정의 접근 차단을 추가했습니다. 잘못된 형식이나 파일이 없는 요청을 거부한 뒤 기존 사진을 보존하는지도 확인했습니다. 교체 후에는 다른 이미지의 실제 바이트로 변경됐는지도 확인했습니다. 추가한 6개 항목은 전체 API 75건에 포함됩니다.

### 통과와 미실행의 구분

작업 종료 시각이 시작 시각보다 빠른 요청을 서버가 받아들여도 SKIP으로 넘기던 검사를 수정했습니다. 현재 계약인 HTTP 400과 DB 무변경을 반드시 검사합니다. 실제 통과를 확인했습니다.

### 서버 의존성 검증

파일 업로드와 설정 병합 라이브러리의 보안 권고를 확인하고 관련 의존성을 갱신했습니다. 개발 도구인 Jest도 30으로 갱신한 뒤 147건을 재실행했습니다. 전체 의존성 감사에서 알려진 취약점 0건을 확인했으며, 이것이 미발견 취약점까지 없음을 보장하지는 않습니다.

설정 병합 라이브러리는 [공식 보안 권고](https://github.com/advisories/GHSA-ggr8-5vv4-36mx)에 따라 보완했습니다. Prisma CLI와 Client 버전은 6.19.3을 유지하며, Prisma 설정 모듈의 deepmerge-ts만 8로 지정했습니다. 코드 생성, 빌드와 마이그레이션 상태 확인도 통과했습니다.

서버 Jest 실행의 줄 커버리지는 86.66%, 분기 커버리지는 66.48%입니다. 실제 API와 화면 실행은 이 계측 수치에 합산하지 않았습니다. 수치가 앱 전체 기능 검증률을 뜻하지는 않습니다.

6개 대조 항목을 6번 실행한 36회 통과입니다. 서로 다른 대조 항목 36개로 세지 않습니다. 모든 실패 메시지를 확인해 의도한 오류에 대한 assertion 실패인지 대조했습니다. 실행 후 수정한 소스가 원본과 동일하고 전용 오류 주입 서버가 종료됐음을 확인했습니다. 복원한 앱에서 관련 8개 항목을 다시 실행해 모두 통과했습니다. [복원 후 실행 결과](evidence/mutation-restored.xml)를 함께 확인할 수 있습니다.
