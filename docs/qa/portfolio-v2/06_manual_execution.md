> 2026-09-18 재작성. 판정, 결함 ID, 근거는 원본(`docs/qa/portfolio/06`, Notion `06_수동테스트` 최종 갱신 2026-08-23, repo 이관 2026-08-27)을 그대로 옮겼다. 바뀐 것은 배치다. 실행 환경 절을 앞에 두고, 결함 기록을 표로 묶고, 탐색 관찰은 16으로 넘겼다. 실행 중 쓴 원본 메모(Notion `관찰 로그 (작업 메모, 8/4 트랙 A)`)는 이관하지 않았다.

#### 이 문서의 위치

ISTQB 4.0 테스트 프로세스의 실행 활동 산출물이다. 실행 활동은 테스트를 수행하고, 실제 결과를 기대 결과와 비교하고, 이상이 있으면 분석해 보고하는 일이다. 이 문서는 29119-3의 테스트 실행 로그 가운데 수동 실행분을 맡는다. 기대 결과는 02의 SPEC, 실행한 케이스는 05의 TC다. 여기 적은 DEF는 실행 시점의 기록이고, 결함을 발견 시점 3범주와 수정 상태로 정리한 인시던트 리포트는 10이 맡는다. API와 서버 DB 층의 실행 기록은 07에 있다.

#### 1. 실행 대상과 환경

| 트랙 | 빌드 | 성격 |

셋째, AI 생성 테스트의 함정을 잡았다. 구현에서 역산해 AI가 쓴 단위 테스트(rejectedPendingLocalOnly)가 QA가 FAIL로 판정한 데이터 유실 동작(SYNC-09)을 정상으로 단언하고 있었다. **AI 생성 테스트가 결함을 회귀 방지 대상으로 고정하는 구조다.** 원본은 이것을 CI 문서와 회고의 핵심 재료로 지목했다.

넷째, 코드 동결 원칙이 실측으로 뒷받침됐다. QA 사이클 중 UX 개선이 카운터 경계값에 회귀(DEF-15)를 만들었고 경계값 테스트가 이를 잡았다. 코드를 바꾸면 2차 회귀가 필요하다는 근거다.

근거와 경위는 다음과 같다.

- DEF-16은 서버에 요청별 Authorization 헤더를 기록하는 임시 계측을 붙여 확인했다. 로그인 200 직후 토큰을 실은 요청 2건이 성공하고 이후 전부 auth=NONE이었다. 원인은 APIClient의 authFailureHandler가 401을 받으면 그 요청이 토큰을 실었는지와 상관없이 세션을 지우는 구조다. 수정은 토큰을 싣고 나간 요청일 때만 세션을 지우는 조건이다. 실기기에서 로그인 후 홈 정상 로드를, 서버 계측 로그로 로그인 이후 전 요청의 Bearer 유지를 확인했다. 실기기의 홈 로드 실패 관찰에서 출발했고, 첫 조사에서 테스트 환경(다중 서버) 탓으로 잘못 판단했다가 재발 보고로 다시 조사해 확정했다. 실패 요청의 무한 재시도(백오프 부재)는 수정 범위 밖이라 열린 관찰로 남는다. 판정은 세션 정합성(치명도 3위 계열) 결함에 무통보 소멸과 재시도 폭주가 더해진 것이다.
- DEF-17은 코드 대조와 저장 상태 실측으로 확정했다. 화면은 세션 종료 시 메모리 상태만 갱신한다(`ProjectWorkspaceViewModel.swift:825`). 저장 쪽 `ProjectRepository.swift`의 saveWorkSession 기본 구현은 세션 배열만 저장한다. 서버도 `projects.service.ts` upsertProjectWorkSession이 WorkSession 행만 만들고 Project.lastWorkedAt을 건드리지 않는다. 홈 필터는 lastWorkedAt이 있는 항목만 보여 준다(`HomeDashboardViewModel.swift:50`). 시뮬레이터의 `projects.json`에서 방금 세션을 기록한 프로젝트 2건 모두 workSessions 1건, lastWorkedAt null이었다. 값이 있는 항목은 생성 시점에 값을 박아 둔 샘플 데이터뿐이다. 영향은 표시 정합성, 정렬 규칙 무력화, 홈 재방문 동선(CUJ-2) 미동작이고 로컬 모드와 서버 모드 공통이다. RC-03 계열이면서 세션 저장과 프로젝트 갱신이 분리된 데이터 계약 문제다. Appium 케이스 설계 중 30개를 시딩하고 작업해도 순서가 안 바뀌는 것을 본 데서 출발했다. 정렬 코드, 세션 10초 규칙을 확인하고 다시 관찰해도 불변이어서 저장 경로를 대조했다. 케이스 설계 시트의 정렬 케이스(TC8)는 FAIL 예상으로 두고 수정 후 회귀로 다시 판정한다.

PDFKitView에 페이지 추적과 복원 로직이 없고, 탭 전환으로 뷰가 다시 만들어지면 위치가 사라진다. 발견 시점에는 명세 공백이었고 스펙 범위를 넓히면서 불일치가 확정됐다(CUJ-2 작업 재개 가치 계열). 뷰어 페이지 유지 케이스 실행에서 발견했고, 기존 PAT-05 실측 PASS(8/4, 스킬 검색 이탈 경로)와 이탈 경로가 다르다는 것을 02 문언과 대조해 판정했다. 8/23 실측에서 스킬과 사전 검색 이탈 복귀는 페이지가 유지되어 PAT-05 기존 약속에 회귀는 없다. 결함은 탭 이동 복귀 경로에 한정되고, 앱 재실행 후 초기화는 약속 범위 밖 관찰로 기록했다. 수정 방향은 페이지 변경을 뷰모델에 보존하고 뷰가 다시 만들어질 때 복원하는 것이다.
