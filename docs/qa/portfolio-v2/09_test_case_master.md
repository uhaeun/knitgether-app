# 09_테스트 케이스 마스터

> 2026-09-18 재작성, 2026-09-19 원본 9/15 갱신분(API 대조표, 번호 미배정 케이스) 반영. TC 그룹, UI와 API 케이스, 판정, 커버리지 집계는 원본(`docs/qa/portfolio/09`, 구글 시트 8/24 기준에 8/29~8/30 실측과 9/15 API 대조를 더한 판)에서 옮겼다. 1차 RTM은 원본 05에서, 8/30 이후 회귀 결과는 원본 11과 12에서 가져왔다. 바뀐 것은 배치다. 추적 사슬을 앞에 두고 케이스 78건 전문 대신 상태별 묶음으로 보인다.

#### 이 문서의 위치

ISTQB 4.0 테스트 프로세스의 설계 활동 산출물 가운데 커버리지 아이템과 추적성을 맡는다. 4.0은 테스트 베이시스, 테스트 조건, 테스트 케이스, 실행 결과, 결함 사이의 추적성을 유지해야 커버리지를 평가하고 변경 영향을 볼 수 있다고 본다. 29119-3 기준으로는 테스트 설계 명세의 커버리지 아이템과 그 추적 정보에 해당한다. 케이스 명세 자체는 05, 실행 로그는 06과 11이 맡는다.

원본 2절과 3절의 `자동/수동`, `판정 근거` 두 열은 2026-08-30에 초안으로 채웠고 QA 검토 전이다. 이 판에서도 검토 전 상태로 둔다.

#### 4. UI 커버리지 아이템 (UI-01~78)

UI 케이스 78건 모두 Appium 함수가 있다(8/27 리포지토리 실측). 함수 하나가 UI-04, 05, 06을 함께 맡고, UI-42와 UI-51은 각각 함수 2개로 나뉜다. 함수가 있다는 것은 존재 사실이고 통과 판정이 아니다.

판정은 두 시점을 따로 적는다. 시트 상태(8/24)는 수동 판정 시점이고, 자동 실행 판정(8/29)은 분할 실행 3회(정방향 2회, 역순 1회)의 결과다. 세 회차 모두 79 passed, 1 skipped, 0 failed였다. skip 1건은 실기기 전용인 UI-42b다.
