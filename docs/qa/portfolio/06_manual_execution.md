#### 핵심 발견

**1. FAIL 9건이 두 원인 계열로 수렴한다.**

개별 화면 버그의 나열이 아니라, (1) 원격 캐시 갱신 시 제거 없이 병합만 하는 전략(DEF-05, 09, 11), (2) 서버 거부 시 무통보 폐기(DEF-03, 04, 12)라는 두 뿌리에서 파생됐다. 결함을 원인으로 묶는 것이 수정 범위와 우선순위를 정한다.

**2. 02의 추정을 실행이 뒤집었다 (CNT-03).**

정적 분석으로 "클라이언트 배열 디코딩 실패"로 추정했으나, 실행 결과 서버가 먼저 500으로 막아 클라이언트는 응답을 받을 기회조차 없었다. 결함 층이 달랐다. 정적 분석의 한계와 실행 검증의 가치를 보여주는 사례다.

**3. AI 생성 코드의 함정을 QA가 잡았다.**

구현에서 역산해 AI가 작성한 단위 테스트가, QA가 FAIL로 판정한 데이터 유실 동작(SYNC-09)을 정상으로 단언하고 있었다. AI 생성 테스트가 결함을 회귀 방지 대상으로 고정하는 구조적 함정이며, 09 CI 문서와 회고의 핵심 재료다.

**4. 코드 동결 원칙이 실증됐다.**

QA 사이클 중 UX 개선이 카운터 경계값에 회귀(DEF-15)를 만들었고, 경계값 테스트가 이를 잡았다. 왜 QA 중 코드를 동결하고 변경 시 2차 회귀가 필요한지를 실측으로 보여준다.

수동 테스트 완주 후 확정 결함을 수정하고 회귀 검증했다(fix/qa-cycle-defects 브랜치, main 대비 36커밋). 상세는 부록 관찰 로그에 있다.

**DEF-16. 로그인 직후 무관한 401 응답이 새 세션을 삭제 (QA 신규 발견, 클라이언트, 수정 완료)**

- 재현: 세션 없는 상태에서 앱이 데이터 요청을 발사한 뒤 로그인. 로그인 이전에 발사된 무토큰 요청의 401 응답이 로그인 완료 후 도착하는 타이밍이면 발생 (경합, 간헐 재현)
- 기대: 로그인으로 발급된 세션은 유지되고 홈 데이터가 로드된다
- 실제: 새 세션과 키체인 토큰이 안내 없이 삭제됨. 이후 모든 요청이 무토큰 401이 되고 401마다 삭제가 반복되며 재시도 폭주 (실측 16,400건). 홈은 로드 실패 표시, 설정은 로그인 폼 (무통보 로그아웃)
- 근거: 서버에 요청별 Authorization 헤더를 기록하는 임시 계측을 붙여 실측. 로그인 200 직후 토큰 실은 요청 2건 성공, 이후 전부 auth=NONE. 원인 코드는 APIClient의 authFailureHandler가 401 수신 시 해당 요청의 토큰 소지 여부와 무관하게 세션을 삭제하는 구조
- 판정: 결함. 세션 정합성(치명도 3위 계열)에 무통보 소멸과 재시도 폭주(자원 낭비) 가중
- 수정: 401 처리 시 토큰을 싣고 나간 요청일 때만 세션을 삭제하도록 조건 추가 (4f7e25e)
- 회귀 검증: 실기기에서 로그인 후 홈 정상 로드, 서버 계측 로그로 로그인 이후 전 요청의 Bearer 유지 확인
- 발견 경로: 실기기 수동 관찰(홈 로드 실패)에서 출발, 서버 계측으로 원인 특정. 첫 조사에서 테스트 환경(다중 서버) 탓으로 오판했다가 재발 보고로 재수사해 확정한 이력을 정직하게 남긴다
- 미해결 잔여: 실패 요청의 무한 재시도(백오프 부재)는 이번 수정 범위 밖, 열린 관찰로 유지
