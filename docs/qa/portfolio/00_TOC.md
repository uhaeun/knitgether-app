# KnitGether Quality Strategy & Release Readiness Portfolio — 목차 (v2, 2026-07-19)

> 목표: 2026-07-26까지 제출 가능한 QA 포트폴리오 완성 (Notion + PDF), 7/28 위버스 지원
> 소재: KnitGether(뜨개더) iOS 앱 + NestJS 서버 — 직접 기획/개발한 앱을 QA 프로세스로 검증
> 축: 목표 회사(위버스·네이버 등)가 요구하는 QA 역량을 산출물로 증명한다

## 최종 구성

1. **프로젝트 포지셔닝** — 앱 소개, 내 역할, 목표 회사 공통 QA 역량표와의 매핑
   - 차별점: "UI–API–DB 3개 레이어에서 데이터 정합성을 검증하는 앱 QA" + DB QA 경력 연결
2. **Quality Bar** — 이 앱의 품질 기준 5~7개 (예: P0 흐름 데이터 유실 0건), 릴리즈 판정의 근거
3. **아키텍처·데이터 흐름** — iOS(SwiftUI/CoreData/Offline-first) + NestJS/Prisma, 동기화 경로
4. **리스크 기반 테스트 전략** — 핵심 사용자 리스크 10개, P0/P1/P2, 범위·제외 범위
5. **RTM** — 요구사항 ↔ TC ↔ 결함 추적
6. **기능별 테스트 케이스** — 정상/경계값/오류/빈 상태/재실행/오프라인/계정 전환 (설계 기법 태그)
7. **수동 E2E 테스트 결과** — 회차별 수치, 재실행·계정 전환·권한·호환성(실기기+시뮬레이터 매트릭스)
8. **API·네트워크·Offline 테스트** — Postman(+DB 상태 검증), Charles 로그, 오프라인/동기화/장애 복구
9. **UI 자동화** — XCUITest POM(핵심 5흐름) + **Appium 동일 흐름 2개 구현·도구 비교표**
   - 비교 축: 셋업 난이도, 실행 속도, 접근성 ID 재사용, CI 연동성 → 도구 선정 근거
10. **CI 품질 게이트** — GitHub Actions: 서버 test, iOS build/unit, (여유 시 Newman) + 실패 artifact
11. **성능 Smoke** — JMeter로 핵심 API 1~2개 (DB QA 시절 JMeter 경력과 연결, 리포트 1장)
12. **대표 결함과 원인 분석** — 재현 절차 + 원인 추적 + 수정 후 재검증 (GitHub Issues 생명주기)
13. **품질 지표·테스트 결과 요약** — 분류별 건수, 커버리지, 잔여 리스크
14. **릴리즈 판단** — Quality Bar 대조표 → Go/No-Go + 근거
15. **회고와 개선 계획** — 못 한 것, 알려진 제한사항 포함

## 결과 분류 (고정)

`PASS` / `FAIL` / `NEED_SPEC_CONFIRM` / `ENV_ISSUE` / `RETRY_REQUIRED` / `NOT_A_BUG` / `ORACLE_DIFF`
