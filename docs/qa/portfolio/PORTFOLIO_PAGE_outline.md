## 3. QA 전략과 리스크 평가 (← 01 + 03)

**이 섹션이 답할 질문.** 무엇이 깨지면 이 제품이 실패하는가, 그래서 어디에 시간을 썼는가.

재료:
- 치명도 5순위 (01): 1 작업물 데이터 유실(동기화 유실 포함), 2 연결 정합성, 3 계정 간 노출, 4 카운트 부정확, 5 도안 열람 불가. "DBMS QA 관점의 연장. FK 제약조건 부재 참조를 최우선 의심 지점으로"라는 문장이 경력 연결 고리다.
- 제품 보장 한 줄 (01): "누른 만큼 정확히 센다. 입력한 만큼 저장되고, 저장된 것은 유실되지 않는다."
- CUJ 3개 (01, 2026-09-01 재분류): 첫 사용(프로젝트 우선과 창고 우선 2경로의 동등성), 재방문 작업 재개, 모르는 기술 만남. 연결의 생애주기는 CUJ가 아니라 정합성 심층으로 옮겼고, 그 재분류 자체가 4절과 7절의 재료다.
- 넓이와 깊이의 배분 (01, 04): CUJ 완주 우선(넓이) + 치명도 1~3위는 악조건 시나리오 심층(깊이). 자동화하지 않은 것도 명시(P1 악조건은 다중 기기, 네트워크 조작, psql 주입이 얽혀 비용이 가치를 초과).
- 결함 클래스 (03): P1 = RC-01 동기화 무이력 유실, RC-02 계정 격리 실패. P2 = RC-03 표시 정합성, RC-04 데이터 계약, RC-05 생성 경로 불일치. P3 = RC-06, RC-07. RC-08은 치명도 축 밖 운영 리스크.
- 리스크 맵이 맞았는지 (12의 3절): 8/30 기준 22건 중 P1 클래스가 10건, 45%. "리스크 기반 설계가 헛돌지 않았다"의 실측 근거.
- 편향 통제 5원칙 (00): 판정 기준의 외부화, 근거의 실측화, 결함의 공개 관리, 기준 커밋 고정, 시점의 구분. 여기서는 이름만, 작동 여부 평가는 7절.

금지: 앱 기능 설명으로 시작하지 않는다. 뜨개 용어(코, 단, 도안)는 "카운터 하한 0"처럼 검증 개념 뒤의 예시로만.

분량 기준: 화면 한 장 이내. 표 하나(치명도 → RC → 등급) 권장.

## 7. 회고 (← 00 편향 통제 자기 평가 + 14 + PROJECT_HISTORY)

**형식.** 못 푼 것 2~3개. 각각 "한계 → 그래서 무엇을 하기로 했나" 세트. 반성문 톤 금지. AI 생성 코드 QA에서 배운 것 명시(티빙 JD의 AI 활용 QA 항목).

못 푼 것 후보:
1. 계정 격리 잔존(RC-02, DEF-05~07 부분 수정). 한계: 세션 생명주기와 저장 디렉토리 재설계가 필요해 QA 사이클 안에서 닫히지 않음. 그래서: AUTH-06 게이트로 로그인 전 노출만 막고 잔존을 15 릴리즈 판정의 조건으로 올림.
2. 되살리기 없는 충돌 처리(SYNC-11 v2.2, 명세 공백 3). 한계: 서버본 우선이 사용자 입력을 버림. 그래서: MVP 스펙으로 확정하고 보관 위치 설계까지만 02에 남김.
3. 정적 점검 8건의 미재현(DEF-22~29). 한계: 마감. 그래서: Critical 1건만 재현하고 나머지는 발견 방법을 명시해 실측분과 섞지 않음.

AI 생성 코드 QA에서 배운 것 (이미 문서화된 사실만):
- AI 단위 테스트(rejectedPendingLocalOnly)가 유실 동작(DEF-03)을 정상으로 단언하고 있었다(14의 1절, README). 통과하는 테스트가 오라클이 아니다.
- DEF-001 "가짜 해결": 앱은 안 고쳐졌고 테스트 헬퍼가 우회하고 있었다(PROJECT_HISTORY 4.3). 테스트 통과 ≠ 근본 원인 수정.
- 코드가 스펙을 먼저 정한 순서 역전: f93aacc가 "정의 없음 15건 해소"라며 상한값과 충돌 정책을 정했고 QA는 사후 승인했다(spec_drift 5절). AI에게 결함 수정을 맡길 때 스펙 결정이 섞여 들어오는 것을 막는 장치가 없었다.
- 핸드오프 known issue 반쪽 이관으로 남의 발견을 QA 발견으로 적을 뻔했다(#9, 10의 4-3절). 기준선에 known issue 전건을 올리는 것이 시점 구분의 전제다.
- 사후 등록 이슈(#18~#39)의 정직성 문제(10의 4-2절). 종료 기준을 세울 때 1인 사이클에서 운용할 도구인지 검증하지 않았다.

편향 통제 5원칙 자기 평가 재료:
- 판정 기준의 외부화: 작동. OBS-3-05(같은 증상이 약속 범위에 따라 결함과 관찰로 갈림)가 증거.
- 근거의 실측화: 작동. 12의 6절 "채우지 못한 지표" 표가 증거.
- 결함의 공개 관리: 반쪽. 사후 등록.
- 기준 커밋 고정: 예외 이력(accessibilityIdentifier, 1차 수정 배치, f93aacc 스펙 결정 혼입)을 적어야 정직.
- 시점의 구분: 한 번 깨질 뻔했고(#9) 정정했다.
