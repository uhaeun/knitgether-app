# 기능정의서 도구, 설정, 홈 (화면 단위)

기능정의서_MVP.md가 다루지 않은 세 영역을 같은 양식으로 정리한 문서다. 동작 기술은 커밋 f93aacc 코드 기준이며, 기획서 v2.2의 해당 절(8 Home, 20~24 Tool, Settings)은 의도 참고로만 썼다. 이 영역은 QA 1차, 2차 사이클의 TC 범위 밖이었으므로 09 문서와의 대응은 없다.

작성: Claude (코드 대조). 판단이 필요한 칸은 정의 없음으로 남겼고, 코드가 기획 의도나 다른 화면과 어긋나는 것은 불일치로 표시했다. 승인과 결함 등록은 하은.

표의 요소 열은 접근성 ID(AppAccessibilityID.swift) 또는 화면의 실제 라벨이다. 예외 처리 열은 코드에서 확인된 것만 적는다.

## 홈 (Views/Home/HomeView.swift, ViewModels/HomeDashboardViewModel.swift)

첫 번째 탭이다. 프로필과 프로젝트 목록을 읽어 요약을 계산하며, 자체 저장 동작은 없다.

| 요소 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 인사 문구 | 표시 | "안녕하세요, {표시 이름}님"과 오늘 날짜(월, 일, 요일) | 표시 이름이 공백이면 "뜨개러" |
| 요약 카드 3개 | 표시 | 전체 프로젝트 수, 진행 중(WIP) 수, 완성(FO) 수 | CO, UFO는 어느 카드에도 세지 않는다. 전체 수에는 포함된다 |
| 누적 작업시간 | 표시 | 모든 프로젝트 totalWorkTime의 합 | 해당 없음 |
| 이어서 작업 카드 | 표시와 탭 | WIP 프로젝트 중 즐겨찾기 우선, 그 안에서 최근 작업 시각(없으면 갱신 시각) 내림차순 첫 항목. 탭하면 작업 공간으로 진입 | WIP가 없으면 "진행 중인 프로젝트가 없어요." |
| 최근 작업 목록 | 표시 | 작업 기록(lastWorkedAt)이 있는 프로젝트를 최근순으로 최대 3개 | 하나도 없으면 "아직 작업 기록이 없어요." |
| 카드 진행률 | 표시 | 총 단수가 있으면 현재 단수 / 총 단수를 0~1로 잘라 표시 | 총 단수가 없거나 0이면 진행률 미표시 |
| 새로고침 (버튼, 당겨서) | 탭 | 프로필과 프로젝트를 다시 읽는다 | 실패 시 배너 "홈 정보를 불러오지 못했어요."와 다시 시도 |
| 화면 진입 | 발생 | 자동으로 한 번 읽는다 | 해당 없음 |

정의 없음: 이어서 작업 카드에서 즐겨찾기가 여러 개일 때의 2차 기준은 최근 작업 시각이며, 작업 기록도 없으면 갱신 시각이다. 이것이 의도인지 확인 필요. 기획서 8절의 "오늘 이어서 할 뜨개" 기준과 대조하지 않았다.

## 게이지 계산기 (Views/Tool/GaugeCalculatorView.swift, ViewModels/GaugeCalculatorViewModel.swift)

| 요소 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 프로젝트 픽커 (tool.gauge.project) | 선택 | 기록과 세탁 전후 비교를 그 프로젝트로 좁힌다. 선택 없음이면 전체 기록 | 프로젝트 목록 조회 실패 시 "프로젝트 목록을 불러오지 못했어요." |
| 도안 픽커 (tool.gauge.pattern), 수동 도안 이름 (manual_pattern) | 선택 또는 입력 | 기록에 도안 이름을 남긴다. 수동 입력이 있으면 그것을 쓴다 | 도안 조회 실패 시 "도안 목록을 불러오지 못했어요." 길이 상한은 정의 없음 |
| 스와치 가로, 세로 (sample_width, sample_height) | 입력 | cm 단위 소수 | 0 이하 또는 비숫자면 "가로/세로 길이는 0보다 커야 해요." 또는 "숫자를 올바르게 입력해 주세요." 안내. 결과 미표시 |
| 스와치 코 수, 단 수 (sample_stitches, sample_rows) | 입력 | 양의 수 | 0 이하면 "코 수와 단 수는 0보다 커야 해요." |
| 목표 가로, 세로 (target_width, target_height) | 입력 | cm 단위 소수 | 0 이하면 "목표 가로/세로는 0보다 커야 해요." |
| 계산 결과 | 표시 | 10cm당 코 수와 단 수(코수/가로 × 10), 목표 코 수와 단 수(코수/가로 × 목표 가로를 반올림) | 여섯 값 중 하나라도 비면 "필수 값을 모두 입력해 주세요.", 전부 비면 "게이지 정보를 입력하면 계산 결과가 표시돼요." 반올림은 .rounded()(0.5는 0에서 먼 쪽) |
| 바늘, 메모 (needle, memo) | 입력 | 기록에 저장 | 길이 상한은 정의 없음(02 명세 공백 5번) |
| 세탁 전 저장, 세탁 후 저장 (save_before, save_after) | 탭 | 현재 입력과 결과를 GaugeRecord로 저장하고 "{단계} 게이지를 저장했어요." | 결과가 없으면 위 안내 문구를 오류로 표시. 저장 실패 시 "게이지 기록을 저장하지 못했어요." |
| 세탁 전후 비교 | 표시 | 선택 프로젝트(또는 전체)에서 세탁 전 최신 1건과 세탁 후 최신 1건을 비교 | 둘 중 하나가 없으면 미표시 |
| 기록 불러오기 | 탭 | 기록 값을 입력란에 채우고 "{단계} 게이지를 불러왔어요." | 불러온 도안 이름이 프로젝트 도안과 다르면 수동 도안 이름으로 채운다 |
| 불러온 기록 수정 저장 | 탭 | 같은 id로 갱신하고 "{단계} 게이지 기록을 수정했어요." | 불러온 기록이 없으면 "수정할 게이지 기록을 먼저 불러와 주세요." |
| 기록 삭제 | 탭 | 삭제 | 실패 시 "게이지 기록을 삭제하지 못했어요." 확인창 유무는 코드에서 확인하지 않음 |
| 상세 게이지 측정 링크 (measure_hub) | 탭 | 아래 상세 측정 허브로 이동 | 온라인 방식에서만 저장소가 연결된다. 없으면 "상세 게이지 저장소가 연결되지 않았어요." |
| 계정 전환 | 발생 | 프로젝트, 기록, 목표, 도안을 다시 읽는다 | 실패 시 "계정 데이터를 다시 불러오지 못했어요." |

불일치: 설정의 기본 단위(Metric, Imperial)는 게이지 계산기와 상세 측정 어디에도 반영되지 않는다. 입력 라벨과 필드 이름이 cm 고정이다. 설정 화면 설명문 "게이지와 길이 입력에서 사용할 기본 단위예요."와 어긋난다. 아래 설정 절 참조.

## 상세 게이지 측정 (Views/Tool/GaugeCalculator/Measure/*, ViewModels/GaugeMeasureViewModel.swift)

목표 게이지(GaugeTarget) 아래 스와치(GaugeSwatch), 스와치 아래 측정(GaugeMeasurement)의 3층이다. 온라인 방식 전용이며 오프라인 캐시가 없다(docs/modes.md 3.6).

| 요소 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 빠른 측정 시작 (measure.quick) | 입력 후 저장 (quick.target_name, quick.needle, quick.save) | 목표, 스와치, 측정을 한 번에 만든다 | 계산기 결과가 없으면 계산기 안내 문구를 오류로 표시 |
| 목표 추가, 편집 (target.add, target.edit, target.form.*) | 저장 | 이름, 바늘, 세탁 후 여부, 가로, 세로, 코 수, 단 수 | 가로, 세로, 코 수가 0 이하이거나 단 수가 음수면 "목표 게이지 값을 올바르게 입력해 주세요." 단 수 0은 허용(단당 환산 0). 저장 실패 시 "목표 게이지를 저장하지 못했어요." |
| 목표 삭제 | 확인 후 삭제 | "목표 게이지를 삭제할까요?" 확인창, "{이름}을 삭제합니다." | 실패 시 "목표 게이지를 삭제하지 못했어요." 하위 스와치와 측정이 함께 삭제되는지는 서버 규칙이며 미확인 |
| 스와치 추가, 편집 (swatch.add, swatch.edit, swatch.form.*) | 저장 | 바늘 사이즈, 종류, 재질, 실 이름, 브랜드, 색상, 로트, 패턴, 메모 | 목표를 찾지 못하면 "목표 게이지를 찾지 못했어요." 필수 항목은 코드에서 확인하지 않음(정의 없음) |
| 수동 측정 (measure.manual_method, measure.width 외) | 저장 | 코 수, 단 수, 가로, 세로에서 10cm당 값을 환산해 저장 | 0 이하 또는 비숫자면 "측정 값을 올바르게 입력해 주세요." |
| 사진 측정 (measure.photo_method) | 사진 선택 → 모서리 4점 지정 → 자동 계산 → 저장 | 4점이 모두 찍혀야 자동 계산 버튼이 활성화된다. 자동 제안값과 신뢰도를 보여주고 사용자가 최종 코, 단 수를 고칠 수 있다. 고친 사실을 저장한다 | 가로, 세로가 0 이하면 저장 버튼 비활성화. 4점 미만이면 "n/4점 선택"과 자동 계산 비활성화. 값 오류 시 "사진 측정 값을 올바르게 입력해 주세요." |
| 세탁 전후 변화 | 표시 | 스와치 안에서 세탁 전과 후 측정이 모두 있으면 코, 단 차이를 부호와 함께 표시 | 한쪽이 없으면 "스와치를 추가하면 세탁 전/후 측정값을 비교할 수 있어요." 계열 안내 |
| 목록 조회 실패 | 발생 | "게이지 측정 목록을 불러오지 못했어요." | 오프라인이면 항상 실패다 |

## 스킬 테스트 (Views/Tool/SkillTest/*, ViewModels/SkillTestViewModel.swift)

온보딩과 설정("스킬 테스트 다시 하기")에서 같은 화면으로 진입한다.

| 요소 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 목록 로드 | 진입 | 스킬 창고의 스킬 전체를 정렬해 카드로 차례로 보여준다. 진행률 "n / 전체" | 실패 시 "스킬 테스트 목록을 불러오지 못했어요."와 다시 불러오기. 스킬이 0개일 때의 화면은 정의 없음 |
| 카드 (현재 스킬) | 표시 | 이름, 현재 상태, 기본 흐름(단계 설명) | 해당 없음 |
| 이해도 선택 | 탭 | 몰라요, 헷갈려요, 잘 알아요 중 하나를 pendingAnswers에 기록 | 선택하지 않고 다음으로 넘어갈 수 있다 |
| 이전, 다음 | 탭 | 인덱스 이동. 첫 카드에서 이전, 마지막에서 다음은 무동작 | 해당 없음 |
| 완료 | 탭 (마지막 카드) | 전체 스킬을 저장하고 결과 요약(전체 수, 상태별 수, 가장 많은 상태) 표시, "스킬 테스트 결과를 저장했어요." | 선택하지 않은 스킬은 기존 상태로 저장된다(정의 없음: 미선택을 "몰라요"로 볼지 유지할지) |
| 나중에 하기 | 탭 | 확인창: 저장하고 나가기(선택한 것만 저장), 저장하지 않고 나가기, 계속하기 | 저장하고 나가기 성공 시 "선택한 스킬 상태를 저장했어요." |
| 저장 실패 | 발생 | 상태 코드별 문구. 연결 실패, 400, 401, 404, 500 이상, 디코딩 실패를 구분 | 아래 불일치 참조 |

불일치: 저장 실패 문구가 개발자용이다. "같은 Wi-Fi와 Local Device 설정을 확인해 주세요.", "Xcode 콘솔을 확인해 주세요.", "서버 Terminal 로그를 확인해 주세요."가 최종 사용자에게 그대로 표시된다. 다른 화면의 실패 문구("~하지 못했어요.")와 수준이 다르다. 결함 등록 후보.

## 프로필 편집 (Views/Tool/ProfileSettingsView.swift, ViewModels/ProfileSettingsViewModel.swift)

| 요소 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 표시 이름 (settings.profile.name) | 입력 | 공백 제거 후 저장 | 비어 있으면 저장 시 "표시 이름을 입력해 주세요." 클라이언트 길이 상한 없음. 서버는 80자에서 400 |
| 기본 단위 픽커 | 선택 | Metric 또는 Imperial | 아래 불일치 |
| 저장 (settings.profile.save) | 탭 | 저장하고 서버 반영 상태 표시 | 실패 시 "프로필을 저장하지 못했어요." |
| 서버 저장 상태, 다시 시도 | 표시와 탭 | 온라인 방식에서 동기화 상태 배지와 재시도 | 재시도 중에는 버튼 비활성화 |
| 로드 | 진입 | 프로필 읽기. 없으면 기본값 | 실패 시 "프로필을 불러오지 못했어요." 로그아웃 상태면 기본값으로 비우고 오류 없음 |

불일치 두 건.
1. 단위 옵션이 화면마다 다르다. 온보딩은 Metric, US(OnboardingViewModel.unitOptions)이고, 회원가입과 프로필 편집은 Metric, Imperial이다. 온보딩에서 US를 고른 사용자가 프로필 편집을 열면 픽커에 해당 태그가 없어 선택 상태가 비고, 저장 시 어떤 값이 나가는지는 실측 필요. 서버 DTO는 문자열만 검사한다.
2. 표시 이름 상한 80자가 회원가입 폼에는 있고(AppInputLimit.displayName) 프로필 편집에는 없다. PROJ-02 범위 안의 같은 필드인데 화면에 따라 다르다. 81자 입력 시 서버 400 후처리에만 의존한다.

## 데이터 백업 (Views/Tool/Settings/DataBackupView.swift, ViewModels/DataBackupExportViewModel.swift)

| 요소 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 백업 파일 만들기 | 탭 | schemaVersion 1 JSON. 프로필, 프로젝트, 도안, 실, 바늘, 도구, 스킬, 사전, 게이지 기록, 실 사용 기록, 도구 연결, 진행 사진(원본 Data 포함)을 담는다. 토큰은 없다. "백업 파일을 만들었어요." | 실패 시 "백업 파일을 만들지 못했어요." 만드는 중 버튼 비활성화 |
| 저장/공유 | 탭 | 공유 시트로 파일 내보내기 | 암호화 없음 |
| 가져오기 | JSON 선택 | 도안, 실, 바늘, 도구, 프로젝트, 스킬, 사전, 게이지 순으로 저장소에 저장. 같은 id가 있으면 synced로 덮어쓰고 없으면 localOnly로 추가. 온라인 방식이면 OfflineFirst를 거쳐 서버까지 반영. 성공 시 건너뛴 사진 수를 포함한 안내 | schemaVersion이 1이 아니면 실패 "백업 파일을 가져오지 못했어요." 파일 선택 실패 시 "백업 파일을 선택하지 못했어요." |

정의 없음 세 건.
1. 같은 id 항목을 확인 없이 덮어쓴다. 되돌리기 없음.
2. 도중 실패 시 앞서 저장된 항목이 남는다. 트랜잭션 없음.
3. 다른 계정의 백업을 가져올 때 ownerId는 서버가 무시하고 현재 계정으로 저장한다(계정 경계는 안전). 이것이 의도한 "계정 간 이동"인지, 막아야 하는지.
