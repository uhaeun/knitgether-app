# 기능정의서 MVP (화면 단위)

기획 명세(docs/spec/원본_v2.2.md)와 개발 과정에서 확정된 동작을 화면 단위로 정리한 문서다. 동작 기술은 현재 코드(main) 기준이며 QA 산출물(02, 05, 09, 10)과 대조했다.

## 범위

포트폴리오 QA가 다룬 MVP 기능만 다루며, TC 그룹(09 문서 1절 TC1~TC16)과 영역을 일치시킨다. 온보딩, 회원가입, 로그인, 로그아웃, 프로젝트 목록(생성, 수정, 삭제, 정렬과 필터, 즐겨찾기, 개수 한도), 작업 공간(도안 영역, 카운터, 정보 탭), 재방문 보존, 창고(실, 바늘, 도구 등록과 수정과 삭제), 오프라인 생성 후 동기화가 대상이다. 그 밖의 기능은 마지막의 범위 외 절에 이름만 적는다.

2026-09-01 갱신: 커밋 f93aacc(정의 없음 해소)를 반영했다. 항목별 대조 근거와 승인 기록은 spec_drift_f93aacc.md에 있다.

표의 요소 열은 코드의 접근성 ID(AppAccessibilityID.swift) 또는 화면의 실제 라벨을 쓴다. 예외 처리 열은 코드에서 확인된 것만 적고, 코드에 해당 처리가 없으면 정의 없음이라고 적는다. 정의 없음 항목은 마지막 절에 모아 정리한다. 기대 결과의 SPEC ID는 02_기능 동작 정의서의 동작 ID를 가리킨다.

## 온보딩 (Views/Onboarding/OnboardingView.swift)

여섯 페이지로 구성된다. 순서대로 도입, 계정, 프로필, 단위, 스킬 테스트, 준비 완료다. 상단 점 표시가 현재 페이지를 나타낸다.

| 요소 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 다음 버튼 (onboarding.start) | 탭 | 다음 페이지로 이동한다 | 저장 중에는 비활성화된다 |
| 이전 버튼 (라벨 "이전") | 탭 | 이전 페이지로 이동한다. 첫 페이지에서는 표시되지 않는다 | 해당 없음 |
| 계정 만들기 / 로그인 (onboarding.login) | 탭 | 계정 화면(AuthAccountView)으로 이동한다. 로그인하지 않고 다음으로 건너뛸 수 있다 | 해당 없음 |
| 이름 필드 (프로필 페이지) | 입력 | 앱에서 쓸 표시 이름을 받는다 | 공백 제거 후 비어 있으면 기본값 "뜨개러"로 저장한다 |
| 단위 세그먼트 (단위 페이지) | 선택 | Metric과 US 중 하나를 저장한다 | 해당 없음 |
| 스킬 테스트 시작 (onboarding.start) | 탭 | 스킬 테스트 화면으로 이동한다. 테스트 자체는 범위 외다 | 해당 없음 |
| 시작 버튼 (onboarding.complete) | 탭 | 프로필을 저장하고 온보딩 완료 플래그를 기록한 뒤 메인 탭으로 진입한다 | 저장 실패 시 "시작 정보를 저장하지 못했어요."를 마지막 페이지에 표시하고 온보딩에 머문다 |
| 화면 전체 | 완료 전 앱 종료 후 재실행 | 첫 페이지부터 다시 시작한다. 진행 중이던 페이지 위치는 저장하지 않는다 | 해당 없음 (완료 플래그만 보존 대상이다) |

## 회원가입과 로그인 (Views/Tool/AuthAccountView.swift)

온보딩 계정 페이지, 설정 탭 계정 카드, 세션 게이트에서 같은 화면으로 진입한다.

| 요소 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 모드 전환 (auth.mode) | 탭 | 로그인과 회원가입 폼을 전환한다. 회원가입 모드에서만 표시 이름과 단위 입력이 나타난다 | 해당 없음 |
| 이메일 필드 (auth.email) | 입력 | 앞뒤 공백을 제거해 전송한다 | @가 없으면 제출 버튼이 비활성화된다 |
| 비밀번호 필드 (auth.password) | 입력 | 마스킹 입력을 받는다. 서버 규칙은 8자 이상 256자 이하다(auth-register.dto.ts) | 8자 미만이면 제출 버튼이 비활성화된다. 256자를 넘는 입력은 256자로 잘라 반영하고 글자 수 카운터를 표시한다(SPEC-PROJ-02) |
| 표시 이름 필드 (auth.display_name) | 입력 | 공백 제거 후 전송한다. 서버 상한은 80자다 | 회원가입 모드에서 비어 있으면 제출 버튼이 비활성화된다. 80자를 넘는 입력은 80자로 잘라 반영한다(SPEC-PROJ-02) |
| 제출 버튼 (auth.submit) | 탭 (로그인) | 성공 시 세션을 저장하고 "로그인했어요."를 표시한다. 토큰은 Keychain에 저장된다(SPEC-AUTH-01) | 자격 오류는 "이메일 또는 비밀번호가 맞지 않아요."로 표시하며 계정 존재 여부를 구분하지 않는다. 연결 실패는 서버 연결 확인 안내를 표시한다 |
| 제출 버튼 (auth.submit) | 탭 (회원가입) | 성공 시 세션을 저장하고 "회원가입이 완료됐어요."를 표시한다 | 중복 이메일은 "이미 가입된 이메일이에요. 로그인하거나 다른 이메일을 사용해 주세요."로 표시한다. 상태 코드별로 400, 401, 409, 500 이상을 구분해 안내한다 |
| 계정 정보 영역 (로그인 상태) | 표시 | 표시 이름, 이메일, 사용자 ID, 기본 단위, 서버 저장 상태 배지를 표시한다 | 계정 정보 조회 실패 시 "계정 정보를 새로고침하지 못했어요."와 재시도 버튼을 표시한다 |

## 로그아웃과 세션 게이트 (Views/Tool/AuthAccountView.swift, ContentView.swift)

| 요소 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 로그아웃 버튼 (auth.logout) | 탭 | 세션만 제거한다(SPEC-AUTH-03). 로컬 데이터는 삭제하지 않고, "로그아웃했어요."를 표시하며 비밀번호 필드를 비운다 | Keychain 삭제 실패 시 "로그아웃하지 못했어요" 얼럿으로 세션이 남아 있음을 알리고 재시도를 제공한다(SPEC-AUTH-03) |
| 세션 게이트 (ContentView) | 세션 없이 앱 진입 | 인증이 요구되는 환경(원격 모드, 정적 토큰 없음)에서는 로컬 캐시를 노출하지 않고 로그인 화면을 표시한다(SPEC-AUTH-06 게이트, SPEC-AUTH-07) | 개발 환경(정적 토큰 주입)에서는 게이트 없이 기존 흐름이 유지된다. 계정 격리의 완전 해소는 미완이며 잔존 결함이 있다(10 문서 DEF-05, DEF-06, DEF-07 부분 수정) |
| 401 응답 수신 | 발생 | 세션만 제거하고 로컬 데이터를 유지한다(SPEC-AUTH-02) | 토큰을 소지한 요청의 401만 세션을 제거한다(DEF-16 수정 반영) |

## 프로젝트 목록 (Views/MyKnitting/MyKnittingView.swift)

| 요소 | 동작 | 기대 결과 | 예외 처리 |

| 추가 버튼 (project.add) | 탭 | 프로젝트 추가 시트를 연다 | 해당 없음 |

| 프로젝트 행 (project.row.{id}) | 탭 | 작업 공간의 뜨는 중 탭으로 진입한다 | 해당 없음 |
| 프로젝트 행 | 길게 누르기 | 수정과 삭제 메뉴를 표시한다 | 해당 없음 |
| 프로젝트 행 | 왼쪽으로 스와이프 | 삭제, 수정, 정보 보기(project.show_info) 버튼을 표시한다. 정보 보기는 작업 공간 정보 탭으로 진입한다 | 해당 없음 |
| 삭제 확인창 | 삭제 선택 | "프로젝트를 삭제할까요?"를 표시한다. 취소 시 유지하고, 삭제 시 tombstone 처리 후 목록에서 제외한다(SPEC-SYNC-06) | 삭제 실패 시 "프로젝트를 삭제하지 못했어요."를 표시하고 항목을 유지한다 |
| 동기화 배너 | 표시 | 서버 저장 확인이 필요한 프로젝트가 있으면 "계정 저장 확인이 필요한 프로젝트가 있어요."와 재시도 버튼을 표시한다 | 해당 없음 |
| 캐시 폴백 배너 | 표시 | 서버 연결 실패로 로컬 데이터를 보여줄 때 "서버와 연결하지 못해 이 기기에 저장된 내용을 보여주고 있어요."를 표시한다 | 해당 없음 |
| 목록 전체 | 당겨서 새로고침 | 프로젝트, 도안, 재료 목록을 다시 불러온다 | 실패 시 "프로젝트를 불러오지 못했어요."와 다시 시도 버튼을 표시한다 |
| 목록 전체 | 계정 전환 감지 | 세션이 바뀌면 목록을 비우고 새 계정 데이터를 다시 불러온다(SPEC-AUTH-04 대응) | 해당 없음 |

| 요소 | 동작 | 기대 결과 | 예외 처리 |

## 작업 공간, 도안 영역 (Views/MyKnitting/ProjectWorkspaceView.swift, Workspace/ProjectPatternFocusView.swift)

작업 공간은 탭 픽커(workspace.tab)로 뜨는 중과 프로젝트 정보를 전환한다. 뜨는 중 탭은 도안 영역과 하단 카운터 시트로 구성된다. 상단에 프로젝트 이름, 상태 배지, 수정 버튼(workspace.project.edit)이 있다. 뷰모델의 오류는 공통 얼럿("오류")으로 표시되고 확인 버튼으로 닫는다.

| 요소 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 도안 메뉴 (workspace.pattern.focus.menu) | 탭 | PDF 직접 추가 또는 교체, 문서 스캔, 도안 창고, 수동 입력, 크게 보기, 사전과 스킬 찾기, 그리기 삭제, 도안 연결 해제 항목을 표시한다. 등록 입구는 5개이며 어느 경로든 결과 형태가 같아야 한다(SPEC-PAT-01) | 크게 보기(workspace.pattern.open_pdf)는 PDF 파일이 없으면 비활성화된다. 그리기 삭제와 연결 해제는 해당 대상이 있을 때만 표시된다 |

## 작업 공간, 카운터 (Views/MyKnitting/ProjectWorkspaceView.swift, Workspace/ProjectCounterPanelView.swift)

| 요소 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 실 등록 (library.yarn.add, 폼) | 저장 | 이름이 필수이고 브랜드, 색상, 굵기, 메모는 선택이다. 수량은 스테퍼로 0에서 999 사이를 받는다 | 이름이 공백이면 저장 버튼(library.yarn.save)이 비활성화된다. 저장 실패 시 "실을 저장하지 못했어요."를 표시한다. 이름은 30자, 메모는 500자 상한이며 클라이언트가 잘라 반영하고 서버(library-save.dto.ts)도 같은 값으로 거부한다(SPEC-PROJ-02) |
| 실 수정 (library.yarn.edit) | 저장 | 창고 목록에 반영된다. 이미 연결된 프로젝트의 스냅샷에는 전파되지 않는다(SPEC-LINK-05) | 등록과 동일하다 |
| 실 삭제 (library.yarn.delete) | 확인 후 삭제 | "실을 삭제할까요?" 확인창을 거쳐 tombstone 처리하고 목록에서 제외한다. 연결된 프로젝트의 참조와 스냅샷은 남아 동일하게 표시된다(SPEC-LINK-04) | 실패 시 "실을 삭제하지 못했어요."를 표시한다. 확인창에 "현재 n개 프로젝트에서 사용 중이에요. 삭제해도 프로젝트에 남긴 기록과 스냅샷은 유지돼요."를 표시한다. 스펙은 연결 기준(SPEC-LINK-10)이나 현재 코드는 사용 기록(ProjectYarnUsage) 기준으로 세어 연결만 된 프로젝트를 0으로 표시한다. 불일치 확정 |
| 바늘 등록 (library.needle.add, 폼) | 저장 | 이름, 종류, 사이즈가 필수다. 사이즈는 표준값 퀵픽 20종과 자유 입력을 함께 제공한다(SPEC-UI-01) | 필수값이 비면 저장 버튼이 비활성화된다. 실패 시 "바늘을 저장하지 못했어요."를 표시한다. 길이 상한은 실과 같다(SPEC-PROJ-02) |
| 바늘 수정과 삭제 | 저장과 확인 후 삭제 | 실과 같은 규칙을 따른다. 수정은 스냅샷에 전파되지 않고, 삭제해도 연결 프로젝트의 스냅샷은 남는다(SPEC-LINK-04, SPEC-LINK-05) | 실과 동일한 형태의 실패 안내를 표시한다 |
| 도구 등록 (library.tool.add, 폼) | 저장 | 이름과 종류가 필수이고 링크와 메모는 선택이다 | 필수값이 비면 저장 버튼이 비활성화된다. 실패 시 "도구를 저장하지 못했어요."를 표시한다. 길이 상한은 실과 같다(SPEC-PROJ-02) |
| 도구 수정 (library.tool.edit) | 저장 | 도구는 스냅샷이 아닌 참조 연결이라 수정이 프로젝트 정보 탭 표시에도 반영된다 | 등록과 동일하다 |
| 도구 삭제 (library.tool.delete) | 확인 후 삭제 | "도구를 삭제할까요?" 확인창을 거쳐 삭제하며, 연결돼 있던 프로젝트의 표시에서도 사라진다 | 실패 시 "도구를 삭제하지 못했어요."를 표시한다 |
| 창고 도안 삭제 (도안 카드 내부) | 확인 후 삭제 | "Library 원본만 삭제돼요. 프로젝트에 가져온 도안 사본은 유지돼요." 확인창을 거쳐 원본만 삭제한다 | 해당 없음 |

## 재방문 보존 (앱 종료 후 재실행)

특정 화면이 아니라 상황 단위로 정의한다. 근거 판정은 09 문서 UI-64와 UI-24, UI-48이다.

| 상황 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 앱 종료 후 재실행 | 발생 | 카운터 값, 도안 연결, 드로잉, 재료 스냅샷, 메모, 목표일, 즐겨찾기 등 저장된 상태가 그대로 표시된다(SPEC-SYNC-04) | 로컬 파일과 저장된 데이터가 모두 없으면 오프라인 에러를 낸다(SPEC-SYNC-04) |
| 재실행 직후 | 발생 | 보류 중 업로드의 자동 재시도는 없다. 재개는 조회 시점에만 일어난다(SPEC-SYNC-07) | 해당 없음 |
| 도안 뷰어 재진입 | 발생 | 프로젝트별로 저장한 페이지 번호를 복원한다(SPEC-PAT-05). 확대율과 스크롤 위치는 복원하지 않는다 | 해당 없음 |
| 온보딩 완료 여부 | 발생 | 완료 플래그가 보존되어 완료한 사용자는 온보딩을 다시 보지 않는다 | 해당 없음 |

## 오프라인 생성 후 동기화

근거 판정은 09 문서 UI-78과 API-18에서 API-20이다.

| 상황 | 동작 | 기대 결과 | 예외 처리 |
| --- | --- | --- | --- |
| 오프라인에서 프로젝트 저장 | 발생 | 로컬 저장은 성공하고 카드에 "이 기기에만 있음" 배지가 표시된다(SPEC-SYNC-01, SPEC-SYNC-02) | 해당 없음 |
| 네트워크 복구 후 목록 조회 | 발생 | 보류 항목의 업로드를 먼저 시도하고 성공 시 배지가 서버 저장됨으로 바뀐다(SPEC-SYNC-04, SPEC-SYNC-07) | 원격 조회 실패 시 로컬을 반환하고 캐시 폴백 배너를 표시한다 |
| 서버가 업로드를 거부 | 발생 | 로컬 데이터를 삭제하지 않고 확인 필요 상태로 보존한다(SPEC-SYNC-09, SPEC-SYNC-10, DEF-03과 DEF-04 수정 반영). 카드 배지가 확인 필요로 표시된다 | 해당 없음 |
| 미동기화 항목 삭제 | 발생 | 로컬 tombstone을 만들고, 서버에 없던 항목은 즉시 제거하며, 서버에 있던 항목은 원격 삭제 성공 시에만 물리 제거한다(SPEC-SYNC-06) | 원격 삭제 거부 시 항목을 복원한다(SPEC-SYNC-06) |
| 동시 수정 충돌 | 발생 | 프로젝트 저장 요청에 마지막으로 알던 서버 갱신 시각(baseUpdatedAt)을 실어 보내고, 서버는 그보다 뒤에 갱신된 프로젝트면 409로 거부하며 서버본을 함께 돌려준다. 클라는 로컬 수정본을 되돌리고 서버본을 다시 받아 표시한 뒤 안내를 띄운다(SPEC-SYNC-11 v2.2). 자식 레코드(작업 세션)는 증분 반영으로 보존된다(SPEC-SYNC-08) | 안내 문구 "확인 후 다시 시도해 주세요"는 수정본이 복원되지 않는 동작과 모순이다. 불일치 확정, 결함 등록 대상. 되돌린 수정본의 되살리기는 명세 공백이다. 카운터 개별 API, 작업 세션, 창고 항목은 충돌 감지 범위 밖이며 현행 last-write-wins다 |
